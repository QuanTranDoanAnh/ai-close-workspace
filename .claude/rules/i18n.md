# Translatable texts

Full rules: `docs/development-standards.md`, section 8. Check: `npm run lint:i18n`.

- Keys are lowerCamelCase segments separated by dots, general to specific: `proposal.approve` (I18N-01).
- Every key has a text-type comment on the line above (I18N-02):

  ```
  #XBUT: Approve a proposal
  proposal.approve=Approve
  ```

- Text types: `XBUT` button, `XTIT` title, `XFLD` field label, `XCOL` column header, `XMSG` and `YMSG` message, `XTOL` tooltip, `XLNK` link, `XACT` accessibility text, `XGRP` group title, `XLST` list item, `XSEL` selection value, `YINS` instruction, `NOTR` not to be translated.
- A key is defined once per file, is never empty, and is removed when it is no longer used (I18N-03, I18N-05, I18N-06).
- Sentences are never concatenated. Use placeholders `{0}`, `{1}` (I18N-08).
- App texts: `app/<app>/webapp/i18n/`. Model texts: `db/_i18n/`. Service texts and messages: `srv/_i18n/` (I18N-09).
- Wording, capitalisation and terminology follow the SAP Fiori UI text guidelines. An error message says what happened and what the user can do (FD-09, FD-13).
- AI notice texts use the wording of `docs/intent-spec.md`, section 9.3.
- No text may suggest that the prototype is an SAP product.
